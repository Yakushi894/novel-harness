# novel-harness（小説生成ハーネス）

[English README](README.en.md) / 設計書：`DESIGN.md`

配布イメージ（Docker Hub）： https://hub.docker.com/r/yuichi894/novel-harness

## 概要

小説生成を **全ローカルで完結**させるための司令塔コンテナです。Synology NAS 上に常駐し、LAN 内の推論 PC（XeStrata / Strata）の OpenAI 互換 API を呼んで、章ごとの生成から改修、結合出力までを工程として管理します。外部サービスへ本文を送らないため、アカウント停止（BAN）リスクがありません。

**Synology Container Manager の GUI からそのまま動かせます。** イメージを起動し、ブラウザの設定画面で接続先を入れるだけです（ターミナル操作・環境変数の編集は不要）。

### ワークスペースと工程

ワークスペースは **物語単位** です。1つの物語（文書）につき1ワークスペースを作り、次の物語は別のワークスペースとして区切ります。各ワークスペースの工程は次の固定フローです。

1. **続き読み込み**：欲しい内容・設定資料を入力。Txt 等の既存テキストを素材として取り込むこともできます（続き生成の起点）。取り込んだ文書には **初期文書解析** を実行でき、モデルが作品概要・登場人物・あらすじ・文体・伏線を解析した基礎資料を作成して、以降の生成すべてに反映します
2. **次章の内容**：章ごとの概要（あらすじ）を一括生成し、Web UI 上で人間が修正・承認
3. **1次出力**：生成前に「プロンプト設計レイヤー」が章専用の生成指示書（文体・視点の維持、流れの受け方、盛り込む／避ける要素）を作成し、それを使って本文を生成。章ごとに要約を作り、次章の文脈に渡します（要約チェーン）
4. **2次修正**：全章がそろったら Synology Chat に「モデルを切り替えて下さい」と通知。推論サーバー側でモデルが切り替わったことを `/v1/models` で検知し、改修を自動開始します。**切替待ちにタイムアウトはありません**（夜中に気づかなくても、生成済み原稿は保持されたまま再開します。再通知あり）
   - 2次修正は「校正」として行います：**全体の意味合い・内容・筋は変えません**。直すのは、てにおは・文法・誤字脱字、日本語としておかしい箇所、内容に合わず混ざった中国語・英語の日本語化だけです（外国人の登場人物がその言語で話すセリフ等はそのまま残します）
   - **スレッドモード（切替なし）も選べます**：作品ごとに選択でき、最初に選んだモデルのまま、章ごとに別スレッド（独立したコンテクスト）で生成→仕上げまで完結します。各スレッドにはアップロードした TXT と章概要を入れ込み、他章の本文は入れないためコンテクスト長を節約できます
5. **PHP・TXT化**：PHP ページ（Web Station）が final の各章を結合し、画面表示と .txt ダウンロードで受け取れます

### モデルは相手先 API 準拠

ハーネス側にモデル名を固定しません。各リクエスト時点で、推論サーバーがサーブ中のモデルをそのまま使います。2次修正は「1次出力で使ったモデルから、ロード中モデルが変わった」ことを検知して始まります（設定で目印文字列を指定することも可能）。

### GUI（AnythingLLM 風レイアウト）

左端のサイドバーにワークスペース一覧と章一覧を常時表示し、メイン領域で工程を進めます。章はサイドバーの ✕ からも削除できます。作品ページはジョブの実行中に自動更新され、各ジョブの所要時間とトークン使用量（thinking メーター）が表示されます。コンテナ再起動で中断されたジョブは、起動時に理由付きで失敗として回収されます。

### 章の最低文字数

作品ごとに章の最低文字数（5000〜50000字）を指定できます。本文が届かない場合、続きを自動で書き足して届かせます（最大5回）。Context Window は 64k／128k／256k／512k から選択でき、各工程の Max Tokens も大きめの既定値になっています。

### 章ページと状態チェーン

各章には独立した **章ページ** があります（章概要 → 生成された本文 → **Think（モデルの思考過程）** → 状態 → 修正要綱）。章ページ下部の **修正要綱** に直したい点を書いてボタンを押すと、その章だけを要綱を含めて再生成できます。

続き書きの状態管理として **状態チェーン** を備えます。初期文書解析の直後に元文書の終了時点の「現在の状態」（現在位置・登場人物の状態・関係・進行中の出来事・未解決の伏線）を出力し、各章は開始時点の状態を入力に受け取り、終了状態を次章へ渡します。入出力状態は章ページで確認できます。

### Web検索と二次創作モード

ローカルモデルが知らない単語・新語・造語のために、Web検索モードがあります。

- **用語検索**：単語を入力すると、日本語 Wiktionary / Wikipedia / Web から意味を調べ、「用語メモ」として保存して以降の生成に反映します
- **用語チェック（自動）**：概要生成と1次出力の前に、モデル自身が「意味を把握できない単語・造語」を指摘し、用語DBになければ検索して追加します。追加時は作品ページのお知らせ欄に記録されます
- **用語DB**：覚えた単語の意味はワークスペースとは別の辞書に保存されます。**ワークスペースを削除しても残り**、別の物語でも同じ単語は2回目から検索に行かずメモを再利用します（サイドバーの「用語DB」から管理できます）
- **二次創作モード**：作品ごとの ON/OFF ボタン（設定で非表示可、初期表示は ON）。ON にすると AI に二次創作であることが伝わります。OFF のときは文面からのみ判断します
- **キャラクター概要の検索**（二次創作 ON のとき）：キャラ名で公開資料を集め、一人称・語尾・口癖・言い回し・立ち振る舞いをまとめた「キャラクター概要」を作成して生成に反映します

外部へ送るのは検索語（単語・キャラクター名）だけで、**原稿本文は外部に送りません**。Web検索は設定で無効化できます。

### 設定画面（AnythingLLM 風）

Web UI の「設定」画面から変更でき、即時反映されます（再起動不要）。

- 接続先URL（XeStrata の API）と API キー（LAN 内でキー不要なら空でOK）
- **Model Context Window**（変更すると各 Max Tokens がその場で自動再配置。初期値は合計で約90%を使う配分で、合計が Window を超えると赤文字で警告が出ます）
- **Context Window（2次修正用）**：2次修正はモデルが変わる前提のため、別枠で用意（既定は最大の 512k、変更時はその80%を Max Tokens に自動設定）。同モデル時は通常配分を流用します
- **Max Tokens**（概要／生成指示書／本文／要約／2次修正ごと）
- Temperature、2次修正モデルの目印、Synology Chat Webhook URL

UI トークンも、LAN 内のみの利用なら不要です（環境変数 `UI_TOKEN` が空なら認証なし）。

## 使い方

### 1. Synology DSM への投入方法（Container Manager）

実機の DSM でも Virtual DSM（vDSM）でも、手順は同じです。前提として、パッケージセンターで **Container Manager** がインストールされていることだけ確認してください。

#### 方法A：GUI だけで投入する（推奨）

1. File Station でフォルダを2つ作る：`/volume1/docker/novel-harness/data` と `/volume1/docker/novel-harness/works`
2. DSM にログインし、**Container Manager** を開く
3. 「レジストリ」で `yuichi894/novel-harness` を検索してダウンロード（タグは `latest`）
4. 「イメージ」からコンテナを作成：
   - ポート設定：ローカルポート `18080` → コンテナポート `8080`
   - ボリューム設定：フォルダ `/volume1/docker/novel-harness/data` → `/data`、フォルダ `/volume1/docker/novel-harness/works` → `/works`
   - 「再起動ポリシー」を有効化
5. コンテナを実行し、ブラウザで `http://<NAS のアドレス>:18080/` を開く
6. 初回は画面に「初回セットアップ」と表示されるので、「設定」画面で推論サーバーの接続先URL（例：`http://192.168.1.10:8080`）を入力して保存

環境変数の設定は不要です（上級者向けの初期値としてのみ使えます。`.env.example` 参照）。UI トークンも LAN 内のみの利用なら不要です。

#### 方法B：プロジェクト（compose）で投入する

「プロジェクト」→「作成」で、下記の `docker-compose.yml` の内容を指定しても同じ構成になります。

```yaml
services:
  harness:
    image: yuichi894/novel-harness:latest
    container_name: novel-harness
    restart: unless-stopped
    ports:
      - "18080:8080"
    volumes:
      - /volume1/docker/novel-harness/data:/data
      - /volume1/docker/novel-harness/works:/works
```

#### バージョン更新の方法

1. 「レジストリ」で `yuichi894/novel-harness:latest` を再ダウンロード（新しいイメージに置き換わります）
2. GUI の場合：コンテナを停止 →「リセット」（イメージの再作成）→ 実行。プロジェクトの場合：「プロジェクト」→「構築」→「実行」
3. データ（作品・設定・用語DB）はすべてボリューム（/data と /works）に保存されるので、コンテナを再構築しても消えません

さらに、設定画面の最下部から **データ一式（DB＋生成ファイル）のバックアップ（zip）をダウンロード／復元** できます。別の環境へ移す場合や、ボリュームごと作り直す場合の引き継ぎに使えます。

### 2. 作品を作って生成する

1. トップ画面でワークスペースを作成（タイトル、欲しい内容、設定資料、章数。素材 TXT は作成時に直接アップロードできます）
2. 必要なら素材の Txt をアップロード（工程1：続き読み込み）
3. 「2. 次章の内容（各章概要）を生成」→ 概要を修正して保存（承認）
4. 「3. 1次出力」→ 章ごとに指示書・本文・要約が自動で作られます
5. 「4. 2次修正」→ Synology Chat に切替依頼が届いたら、推論 PC で修正用モデルに切り替えてください。検知後に改修が自動で進みます
6. 完了したら PHP ページ（または作品ページのダウンロード）から結合テキストを取得

### 3. PHP 出力ページの配置

`php/index.php` を Web Station のサイトに配置し、冒頭の `WORKS_ROOT` を作品フォルダの実パスに合わせてください。final 状態の章がある作品が一覧表示され、画面から .txt をダウンロードできます。

出力ページは読みやすく整形された読書ページです（明朝体・段落整形・目次・章見出し・横書き／縦書き切替）。作品タイトルと章タイトルは DB から引いて表示します（DB が読めない環境ではフォルダ名と章番号で表示）。PHP を更新したときは、このファイルの差し替えが必要です。

## 構成

- `app/` … FastAPI アプリ本体（工程管理、生成ドライバ、プロンプト設計レイヤー、設定画面、Synology Chat 通知、モデル切替の検知）
- `docker-compose.yml` … 本番用（Docker Hub のイメージを使用、環境変数なしで動作）
- `docker-compose.dev.yml` … 開発・検証用（ソースからビルド）
- `php/index.php` … Web Station 用のまとめ出力ページ
- データは SQLite（`/data`）と作品フォルダ（`/works`）に保存されます

## 注意点

- 推論サーバー（Strata 系）の serve API には **モデル切替 API がありません**（load/unload のみ）。そのため 2次修正は「通知＋手動切替＋自動検知」で回す設計です
- 思考トークンは出力上限の内数です。上限は設定画面の Max Tokens で調整でき、Context Window を変えると自動で再配置されます
- UI は LAN 内＋Tailscale での利用を想定しています。インターネットへ直接公開しないでください
- Muse による監修は任意レーンです（作品ごとに「Muse 監修レーン可」を付けた原稿だけが対象。それ以外は Muse ノータッチ）
